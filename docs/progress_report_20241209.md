# 進捗報告書（2024/12/2〜12/9）

## 概要

前回のミーティング以降、レポート品質の大幅な改善とシステム安定性の向上を行いました。

---

## 1. レポート品質の改善

### AIによるデータ捏造の防止

**問題**: AIが存在しないデータ（価格、目標金額、達成率、残り日数など）を勝手に生成していた

**対応**:
- 取得できたデータのみをレポートに記載するよう厳格化
- キャンペーンの状態（継続中/終了）の推測を禁止
- 価格情報は「Kickstarterページでご確認ください」と案内する形式に変更

**結果**: 信頼性の高い、事実に基づいたレポートを生成

### 根拠に基づく提案の実装

**問題**: 「目標金額1,000万円を推奨」など、根拠のない数値が記載されていた

**対応**:
- 類似製品のデータ（例: Duovox 4,629,102円）を根拠として引用
- 類似製品が見つからない場合は正直に「市場調査後に決定」と記載

**例**:
> Before: 「目標金額1,000万円を推奨します」
>
> After: 「Duovox Ultra Proの4,629,102円の成功実績を基に、目標金額約1,000万円を推奨します」

---

## 2. 検索機能の改善

### 不適切な検索結果の排除

**問題**: カテゴリ検索（例:「カメラ」）で無関係な製品（カメラバッグ、陶器など）がヒットしていた

**対応**:
- 汎用的なカテゴリ検索を廃止
- GPTが生成する製品固有のキーワードのみで検索
- キーワードを最大2つに制限し、精度を向上

**結果**: 関連性の高い類似製品のみを取得

---

## 3. システム安定性の向上

### Kickstarterボット検出対策

**問題**: 連続アクセスでボットとして検出され、データ取得が失敗していた

**対応**:
- 各製品処理後にブラウザを完全リセット
- リクエスト間の待機時間を最適化（10秒）

**結果**: 安定したデータ取得を実現

### Selenium → Playwright 移行

**対応**: より安定したPlaywrightに移行完了

**メリット**:
- GitHub Actionsでの動作が安定
- メモリ使用量の削減
- エラー発生率の低下

### Bright Data プロキシの導入

**問題**: CAMPFIREが海外IPからのアクセスを制限しており、GitHub Actions（米国サーバー）からデータ取得ができなかった

**対応**:
- Bright Data（プロキシサービス）を導入
- 日本のIPアドレス経由でアクセス可能に
- 通常は直接接続を試み、失敗時のみプロキシを使用（コスト最適化）

**結果**:
- CAMPFIREからの類似製品データ取得が可能に
- Makuake + CAMPFIRE の両方で日本クラウドファンディング市場をカバー
